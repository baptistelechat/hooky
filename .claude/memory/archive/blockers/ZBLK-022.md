# ZBLK-022 — Double Stop/son/notification : plusieurs fausses pistes avant la vraie cause

| Friction                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Cause réelle                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Solution                                                                                                                                                                                                                                                                                       | Statut |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| Un vrai "Stop" (tâche terminée) déclenchait parfois deux (voire trois) sons/bulles de notification, de façon intermittente, résistant à plusieurs corrections successives. Fausses pistes explorées avant la bonne : bug frontend React StrictMode (réel, cf. [LRN-042](../../learnings/LRN-042.md), mais insuffisant seul) ; interférence entre deux sessions Claude Code partageant le même serveur Hooky global (écartée par le timing rapporté par Baptiste) ; écho d'un fork système invisible sans `agent_id` détectable (fix partiel appliqué mais insuffisant, un "Stop" ré-émis restait possible si le fork avait lui-même utilisé des outils entre-temps). | `spawn_idle_reaper` (tick périodique 10s) gardait son propre suivi de dédoublonnage (`last_emitted: Option<String>`) totalement séparé de celui du handler principal `on_event`. Dès qu'un vrai hook émettait un état, le tick suivant du reaper (jusqu'à 10s après) le trouvait "nouveau" de son propre point de vue et le réémettait — récidive d'un pattern déjà documenté ([LRN-017](../../learnings/LRN-017.md)) dont le fix précédent n'avait corrigé que le contenu du payload, pas le suivi de dédoublonnage lui-même. Confirmé via un log exhaustif entrée/sortie de `/event` (dont les champs officiels `stop_hook_active`/`prompt_id`, cf. [LRN-044](../../learnings/LRN-044.md)), montrant un seul vrai `Stop` reçu mais deux séquences émises. | Le reaper partage désormais le même suivi (`state.last_emission`, `Arc<Mutex<...>>`) que `on_event`, avec une comparaison stricte de signature sans tolérance de fenêtre temporelle (contrairement à `on_event`, qui doit pouvoir rejouer un vrai 2e Stop réel après `DUPLICATE_EMIT_WINDOW`). | résolu |
