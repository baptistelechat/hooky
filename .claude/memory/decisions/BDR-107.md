# BDR-107 — Mod hooky-pet : simple lecteur de GET /state

| Décision | Pourquoi | Alternatives considérées | Statut |
| --- | --- | --- | --- |
| Le mod Claude Code `hooky-pet` ne contient aucune logique d'événements : il lit `GET /state` (backend Rust, `publish_state`) toutes les 500 ms et affiche le sprite de l'animation et de l'avatar renvoyés | Le backend agrège multi-sessions, filtre les forks invisibles et les `Stop` en double, gère timeouts et `sleeping` ; réimplémenter ça dans le mod donnait un pet désynchronisé (4 états sur 10). L'avatar actif vit dans la WebView : seul Hooky le connaît | Mod qui mappe lui-même les hooks Claude Code (v1, abandonné) ; module `Client` avec le moteur (1 appel/s, pas de DOM) ; relais POST vers la fenêtre Hooky ; réécriture des 23 animations en SMIL | actif |
