# BDR-026 — Clé de session (session_id, agent_id) au lieu de session_id seul

| Décision                                                                                                                         | Pourquoi                                                                                                                                                                                                                                                                                                                                                                     | Alternatives considérées                                                                                                                                                                                                             | Statut |
| -------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------ |
| La map `Sessions` est keyée par `(session_id, agent_id)` (nouveaux types `SessionKey`/`SessionMap`) au lieu de `session_id` seul | Un sous-agent (Task explicite ou fork système type auto-mémoire) partage le `session_id` de sa session parente mais porte son propre `agent_id` (confirmé par la doc officielle des hooks Claude Code, voir [LRN-023](../learnings/LRN-023.md)) — sans distinction, un `SubagentStop` tardif écrasait l'entrée `celebrate` du `Stop` parent (même clé = même entrée écrasée) | Guard ad-hoc dans `on_event` ("ignorer un `SubagentStop`/`PostToolUse`/... si la session est déjà en `celebrate`") — écarté : patch de symptôme fragile, recasse dès que l'ordre réel des hooks change ou qu'un nouveau cas apparaît | actif  |

`SessionEnd` a été adapté en conséquence : il purge désormais toutes les entrées d'un `session_id` (parent + sous-agents), pas une clé exacte unique.
