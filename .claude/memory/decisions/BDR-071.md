# BDR-071 — Backoff exponentiel sur l'endpoint usage rate-limité, révise BDR-070

| Décision                                                                                                                                                                                                                                                                                                                                    | Pourquoi                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Alternatives considérées                                                                                                                                                                                                                                                                                                                                                                                                          | Statut |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| `spawn_usage_poller` (`src-tauri/src/lib.rs`) : backoff exponentiel sur échec (`usage_backoff_delay`, 60s doublé par échec consécutif jusqu'à 900s plafonné) au lieu d'un retry fixe 15s. Le cache `LastUsage` n'est mis à jour QUE sur succès -- une erreur ne l'écrase jamais et n'émet rien, le panneau garde la dernière valeur connue. | Un utilisateur a rencontré un vrai 429 de `api/oauth/usage` après une salve de redémarrages (install v0.2.0 + tests) : le retry fixe 15s martelait l'endpoint pendant qu'il restait rate-limité, et une erreur écrasait le cache en `{"error": ...}` -- indistinguable de "pas encore chargé" côté front, panneau bloqué sur "Chargement…" indéfiniment. Recherche du comportement de projets équivalents (claude-pulse, ccstatusline) : ils interrogent le même endpoint sans jamais déclencher de 429 grâce à un backoff + une valeur de repli en cache pendant le blocage. | Passer par le hook `statusLine` de Claude Code (zéro appel API direct, données poussées par le CLI) -- écarté : ne couvre que `five_hour`/`seven_day`, perd le détail par modèle (`weekly_scoped`, cf. [BDR-069](../decisions/BDR-069.md)) ; espacer le poll à 30-60min -- écarté par Baptiste, dégrade la fraîcheur des quotas sans traiter la cause réelle (le problème était le retry sans backoff, pas la fréquence de 3min). | actif  |
