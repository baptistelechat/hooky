# BDR-050 — Avatar centré fixe dans la fenêtre, bulle en position absolue

| Décision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Pourquoi                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | Alternatives considérées                                                                                                                                                                                                                                                                              | Statut |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| L'avatar occupe désormais une position TOUJOURS centrée dans la fenêtre (`avatarCenterOffsetY`, indépendante de `flipped`) -- un flip ne déplace donc plus jamais l'avatar ni la fenêtre. Seule `bubble-zone`, en position absolue, bascule au-dessus ou en-dessous de l'avatar selon `flipped` (`top`/`transform`, swap CSS local). La fenêtre passe de 330 à 420px de haut pour réserver l'espace bulle des DEUX côtés de l'avatar (au lieu d'un seul). Motion (`layout`) est abandonné. | Root cause du flash persistant malgré [BDR-049](BDR-049.md) : dans l'ancien schéma, l'offset de l'avatar dans la fenêtre dépendait de `flipped`, donc chaque flip devait repositionner la fenêtre (`setPosition()`, IPC Tauri asynchrone) en compensation du changement CSS (synchrone) -- ces deux mises à jour ne pouvaient jamais être parfaitement atomiques, créant un flash inévitable (l'avatar apparaît une frame à "ancienne position fenêtre + nouvel offset"). Rendre l'offset de l'avatar CONSTANT élimine le besoin de toute compensation : plus rien à synchroniser entre CSS et IPC. | Continuer à patcher la synchronisation CSS/IPC (compensation d'offset, synchronisation de ref d'état) -- écarté après plusieurs rounds sans succès (cf. [BLK-025](../blockers/BLK-025.md)) : le problème est un séquencement inter-process, pas une incohérence de state corrigeable côté React seul. | actif  |
