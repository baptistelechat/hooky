# LRN-031 — `<input type="color">` : onChange React = event natif "input" continu

**Pattern observé** : React lie `onChange` sur `<input type="color">` à l'event natif "input" (fire en continu pendant qu'on drague dans le picker), pas à "change" (fire une seule fois à la fermeture du picker) -- committer un traitement coûteux (state global, IPC cross-fenêtre, rebuild) sur chaque tick d'"input" cause un lag visible.

**Contexte** : Chaque frappe du color picker de `AvatarPicker` déclenchait un `setSettings` + `emit` Tauri + rebuild avatar (`createAvatar`), rendant le picker et le pet flottant lourds pendant le drag (cf. [ZBLK-015](../archive/blockers/ZBLK-015.md)).

**Application future** : Garder un état local instantané (draft) pour l'aperçu visuel, piloté par `onChange` (React, continu) ; n'écouter le "change" natif (via `ref` + `addEventListener`) que pour committer vers un état coûteux à propager.
