# LRN-010 — Container query : réutiliser le contexte nommé du design system plutôt qu'un breakpoint viewport parallèle

| Pattern observé                                                                                                                                                                                                                                                                                                                                                                                                                        | Contexte                                                                                                                                                                       | Application future                                                                                                                                                                                                                                                                  |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Un composant de design system (ici `Field`/`FieldGroup` de shadcn) établit déjà un contexte `@container/nom` pour ses propres besoins responsive. Un nouvel élément ajouté à l'intérieur doit réutiliser le même breakpoint nommé (`@md/nom:flex-row`) plutôt qu'introduire un breakpoint Tailwind viewport (`md:flex-row`), qui suivrait un seuil différent et créerait une incohérence de largeur de bascule au sein du même panneau | Boutons Exporter/Importer/Réinitialiser (fenêtre settings Hooky) : passage en pleine largeur empilée sous le seuil déjà utilisé par le composant `Field` "responsive" existant | Avant d'ajouter une classe responsive Tailwind à un élément imbriqué dans un composant de design system, grep `@container` dans le composant parent — réutiliser ce même contexte/seuil plutôt que mélanger deux stratégies de bascule (container vs viewport) dans le même panneau |
