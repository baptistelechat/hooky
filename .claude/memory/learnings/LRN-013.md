# LRN-013 — Un outil d'export tiers peut violer le schéma de validation runtime qu'il alimente

| Pattern observé                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Contexte                                                                                                                                                                                                                                                                  | Application future                                                                                                                                                                                                                                                                                                              |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Le Studio (outil d'export visuel officiel `bible-strong`) autorise `tipRoundness`/`baseRoundness` jusqu'à 2 et `morphRoundness` au-delà de 1 via son UI, mais le schéma JSON de validation runtime (`@bible-strong/avatar-core`, ajv strict) plafonne ces 4 champs à 1 (`$defs/roundness`). Le composant `Avatar` du package valide la définition à chaque montage et **throw** de façon synchrone si invalide -- sans error boundary autour, React démonte tout l'arbre : fenêtre transparente vide, aucune trace d'erreur visible, backend/tray Rust totalement intacts (process séparé). | Avatar "Onee" (export du Studio, `tipRoundness`/`baseRoundness`: 2) chargé en remplacement de "Cubee" -- l'avatar disparaissait après relance, aucun symptôme backend, diagnostic remonté jusqu'au schéma ajv en lisant le dist du package (`@bible-strong/avatar-core`). | Face à une UI "vide sans erreur" après avoir chargé une donnée générée par un outil tiers (export, config, template), remonter au schéma de validation qui consomme cette donnée plutôt que de chercher côté process/réseau -- et clamper/normaliser les valeurs hors bornes en amont plutôt que de faire confiance à l'export. |
