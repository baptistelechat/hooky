# LRN-002 — Drag & drop cassé par permission Tauri v2 absente de `core:default`

| Pattern observé                                                                                                                                                                                 | Contexte                                                                                                                                                                                                                                               | Application future                                                                                                                                                                               |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `core:default` (Tauri v2) ne couvre pas `start_dragging` — sans `core:window:allow-start-dragging` explicite dans `capabilities/default.json`, l'appel `startDragging()` échoue silencieusement | Deux approches essayées semblaient également cassées : `data-tauri-drag-region` (ne relayait pas fiablement car le SVG est monté impérativement par le moteur d'animation) puis `getCurrentWindow().startDragging()` en JS explicite sur `onMouseDown` | Sur toute feature Tauri v2 qui échoue silencieusement (pas d'erreur JS visible), vérifier en premier les permissions dans `capabilities/*.json` avant de re-questionner l'implémentation JS/HTML |

Confirmé via `src-tauri/gen/schemas/acl-manifests.json` (identifiant de permission réel et valide) et `capabilities.json` généré (permission bien résolue/active dans le binaire compilé — `cargo check` ne l'aurait pas laissé passer sinon).
