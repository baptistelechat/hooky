# LRN-057 — CSS synchrone vs repositionnement de fenêtre OS asynchrone = flash structurel

| Pattern observé                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Contexte                                                                                                                                                                                                                                                                                                                                                                                  | Application future                                                                                                                                                                                                                                                                                                                                                 |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Dans une app desktop (Tauri/Electron), si un changement CSS (synchrone, peint dès la prochaine frame) doit rester coordonné avec un repositionnement de fenêtre OS (`setPosition()`, passe par l'IPC -- toujours un peu plus lent) pour éviter un flash visuel, ces deux mises à jour ne peuvent JAMAIS être parfaitement atomiques. Peu importe la précision de la synchronisation côté state (refs, callbacks synchrones) : le décalage vient du séquencement inter-process, pas d'une incohérence corrigeable côté JS seul. | Hooky : l'offset de l'avatar dans la fenêtre dépendait de `flipped` -- chaque flip nécessitait un `setPosition()` compensatoire pour garder l'avatar à la même position absolue à l'écran, toujours en léger retard sur le changement CSS (`order`/`justify-content`). Plusieurs rounds de correction côté state (compensation d'offset, ref synchronisée) n'ont jamais éliminé le flash. | Face à ce symptôme, ne pas chercher à mieux synchroniser CSS et IPC -- restructurer pour que la position qui change en CSS ne dépende JAMAIS d'un repositionnement de fenêtre (ex: rendre l'élément concerné à position FIXE dans la fenêtre, indépendante de l'état qui change). Élimine la classe de bug à la racine plutôt que de réduire la fenêtre de course. |
