# LRN-086 — Valider un fix asynchrone via corrélation d'horodatages, sans observation directe

| Pattern observé                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Contexte                                                                                                                                                                                                                 | Application future                                                                                                                                                                                                                                                                                                                                                                                                |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Confirmé que le refresh OAuth de [BDR-073](../decisions/BDR-073.md) avait fonctionné SANS observer directement l'UI ni les logs live : `LastWriteTime` du fichier `.credentials.json` (11:32:57) correspondait exactement à l'instant de démarrage du process `hooky.exe` visible dans le terminal, et `expiresAt` valait précisément ce timestamp + 8h (durée de vie connue du token) -- deux faits indépendants qui ne coïncident que si le refresh a réussi. L'absence de toute ligne `[hooky-usage]` d'erreur dans le terminal confirmait l'absence d'échec (le code ne logge que les échecs et les reprises après échec, jamais un succès silencieux). | Validation du fix de [ZBLK-033](../archive/blockers/ZBLK-033.md) le lendemain, sans accès à un screenshot de la bulle ni à un log dédié -- seules preuves disponibles : métadonnées fichier + terminal de l'utilisateur. | Face à un fix asynchrone (retry, cache, token) impossible à observer directement, chercher deux faits indépendants qui ne peuvent coïncider que si le fix a réussi (ex. horodatage fichier + valeur dérivée qu'il contient), et vérifier l'absence des logs d'erreur qui apparaîtraient sinon -- un faisceau de preuves indirectes concordantes vaut une observation directe quand celle-ci n'est pas disponible. |
