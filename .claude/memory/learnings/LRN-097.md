# LRN-097 — Tester du canvas : page servie en HTTP local, même origine

| Pattern observé | Contexte | Application future |
| --- | --- | --- |
| Pour tester du code canvas sur des images réelles dans un vrai navigateur : copier les assets dans un dossier de travail, y écrire une page de test (module inline reprenant l'algorithme), lancer `python -m http.server <port> --bind 127.0.0.1` dans ce dossier, ouvrir la page dans le navigateur intégré et lire le résultat avec `get_page_text`. Même origine → canvas non « tainted », `getImageData` fonctionne. Arrêter ensuite le serveur (`Stop-Process` sur la ligne de commande `http.server`). | Validation de `rowFrameCounts` sur les 8 pets WebP installés : résultat identique à une mesure Pillow faite avant, de façon indépendante (`idle` = 7 sur les 2 pets v2, 6 sur les 6 pets v1). Deux implémentations qui concordent valent mieux qu'une seule. | Pour toute logique qui dépend du décodage du navigateur (alpha d'un WebP, rééchantillonnage), préférer ce test au canvas simulé de [LRN-096](LRN-096.md) quand le navigateur intégré accepte l'origine locale ; copier les assets plutôt que servir le dossier de l'utilisateur ; refermer le serveur en fin de test. |
