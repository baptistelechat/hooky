# LRN-059 — Une ref miroir d'un state doit être mise à jour de façon synchrone au même call site, jamais via un `useEffect` séparé

| Pattern observé                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Contexte                                                                                                                                                                                                                                                                                                                                                           | Application future                                                                                                                                                                                                                                                                                                                                        |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Quand une ref sert à refléter la dernière valeur d'un state pour qu'un code CONCURRENT/ASYNCHRONE (un autre event handler, un callback externe déclenché par de l'IPC) puisse la lire sans attendre un re-render, synchroniser cette ref via `useEffect(() => { ref.current = state }, [state])` laisse une fenêtre d'un cycle de rendu COMPLET où la ref reste périmée (un effet ne s'exécute qu'après le rendu/paint, derrière l'appel à `setState`). Si un événement concurrent survient dans cette fenêtre, il lit l'ancienne valeur et peut annuler la décision qui venait d'être prise. | `useAvatarScreenLayout` (Hooky) : `flippedRef`, censée refléter l'état `flipped` pour un calcul déclenché par `onMoved` (lui-même déclenché par les propres `setPosition()` de l'app, donc très fréquent) -- synchronisée via `useEffect` séparé, créait une fenêtre de course exploitée à chaque frame de drag, causant un flash "avatar qui saute puis revient". | Pour ce genre de ref, exposer une fonction locale qui met à jour la ref ET appelle `setState` dans le MÊME appel synchrone (`const setXAndRef = (v) => { ref.current = v; setX(v) }`), plutôt que de déléguer la synchronisation à un effet réactif -- élimine la fenêtre de course entièrement, quelle que soit la fréquence des événements concurrents. |
