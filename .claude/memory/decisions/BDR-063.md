# BDR-063 — Taille CSS de l'avatar synchronisée sur le resize OS débouncé, pas sur `settings.avatarSize` live

| Décision                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Pourquoi                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Alternatives considérées                                                                                                                                                                                                                                                                                                                                               | Statut |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| Nouveau state local `renderedAvatarSize` dans `Avatar.tsx`, distinct de `settings.avatarSize`. Le CSS de l'avatar (slot, `FittedAvatarEngine`, `AnimationOverlay`, clamp de drag) suit désormais `renderedAvatarSize`, mis à jour dans le MÊME `setTimeout` (120ms, déjà en place) que l'appel `setSize()` OS sur la fenêtre "main" — `settings.avatarSize` (qui change à chaque tick du slider Settings) ne sert plus qu'à déclencher ce timeout, plus à peindre directement. | Retour utilisateur : en augmentant la taille via le slider Settings, l'avatar était rogné par le bord de la fenêtre AVANT que celle-ci n'ait fini de se redimensionner, avec un rendu global "saccadé" — régression identifiée par archéologie git : avant [ZBDR-052](../archive/decisions/ZBDR-052.md) (fenêtre "main" alors fixe 480×420, jamais redimensionnée par `avatarSize`), le CSS animait sa taille en toute liberté à l'intérieur d'une fenêtre déjà assez grande, sans jamais heurter ses bords. Depuis le passage à une fenêtre dynamiquement dimensionnée sur `avatarSize`, le CSS (instantané) et le `setSize()` (débouncé 120ms) pouvaient diverger transitoirement — cf. [LRN-071](../learnings/LRN-071.md) pour le pattern extrait. | Réduire ou supprimer le debounce pour resynchroniser plus vite — écartée : le commentaire d'origine (cf. commit `f93be8f`) documente déjà qu'un `setSize()` à chaque tick de slider (dizaines par seconde) est visuellement "saccadé" (WebView2 doit re-layouter toute la surface), donc réduire le délai n'aurait fait qu'atténuer la fenêtre du bug sans l'éliminer. | actif  |
