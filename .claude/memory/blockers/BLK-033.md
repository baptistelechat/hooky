# BLK-033 — "Chargement…" persistant malgré le fix backoff (révise ZBLK-032)

| Friction                                                                                                                                                                                                                     | Cause réelle                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Solution                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Statut |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| Bulle bloquée sur "Chargement…" depuis 19h30 (constaté à 22h30, soit 3h) alors que [BDR-071](../decisions/BDR-071.md) (backoff exponentiel) était censé régler ce symptôme dans [ZBLK-032](../archive/blockers/ZBLK-032.md). | Deuxième cause, distincte du rate-limit initial : le token OAuth local (`~/.claude/.credentials.json`) était expiré depuis **3 jours**, jamais rafraîchi. Seul le CLI `claude` en terminal rafraîchit ce fichier (via son `refreshToken`) -- Baptiste n'utilise quasiment plus que l'app Desktop (onglet Code), qui ne le touche jamais. `fetch_usage` retentait donc en boucle avec un token mort, l'API renvoyant 429 au lieu d'un 401 propre pour ce cas. Confirmé en relançant `hooky.exe` avec stderr redirigé (`fetch_usage a échoué : l'API usage a répondu 429`) puis en vérifiant `expiresAt` via PowerShell, et en observant qu'une vraie session `claude` déclenchait bien le refresh (`expiresAt` passé de 3 jours dans le passé à ~8h dans le futur). | Refresh OAuth direct implémenté côté Hooky (cf. [BDR-073](../decisions/BDR-073.md)) + garde-fou UI distinguant chargement/échec (cf. [BDR-074](../decisions/BDR-074.md)). **Non validé en conditions réelles** : le test réseau live de l'endpoint de refresh a lui-même échoué en 429 (cf. [LRN-084](../learnings/LRN-084.md)) -- le rate-limit externe semble couvrir tout `/v1/oauth/*` du compte au moment de la session, pas que l'endpoint usage. Commit livré en 🚧 (WIP) plutôt que 🐛 pour signaler ce doute. À revérifier au prochain cycle réel (le token courant expire ~06h37 le 2026-09-12) : succès si les logs `[hooky-usage]` ne montrent plus d'échec après cette heure, ou si la bulle affiche les rings de quota. | ouvert |
