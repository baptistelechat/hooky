# LRN-016 — Windows anti-focus-stealing : `setFocus()` seul insuffisant pour ramener une fenêtre Tauri au premier plan

**Pattern observé** : `WebviewWindow.setFocus()` appelé seul ne ramène pas fiablement au premier plan une fenêtre Tauri déjà ouverte mais passée en arrière-plan (une autre appli a le focus) ou minimisée -- Windows refuse silencieusement de voler le focus à l'appli active (anti-focus-stealing), même pour une fenêtre de la même appli/process appelante.

**Contexte** : `openSettingsWindow()` : le double-clic sur l'avatar pour rouvrir les settings déjà ouverts ne les ramenait pas au premier plan si une autre appli avait le focus entre-temps.

**Application future** : Systématiquement enchaîner `show()` puis `unminimize()` puis `setFocus()` (dans cet ordre) pour ramener une fenêtre Tauri existante au premier plan sur Windows -- `setFocus()` seul est insuffisant dans les cas arrière-plan/minimisé, et c'est le contournement communément documenté dans l'écosystème Tauri.
