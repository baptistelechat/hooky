# ZBLK-031 — Premier run réel du pipeline de release : 3 surprises enchaînées

| Friction                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Cause réelle                                                                                                                                                                                                                                                                                                                                                           | Solution                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Statut |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| Premier tag `v0.1.0` poussé → CI en échec en 8s. Diagnostic + fix ([LRN-075](../../learnings/LRN-075.md)) → re-tag en `v0.1.1` (bump patch pour repartir sur un arbre git propre) → CI réussie, mais Baptiste ne trouvait ni release ni `.exe` en regardant la sidebar repo et l'onglet `/tags` ([LRN-076](../../learnings/LRN-076.md)) → une fois la release localisée (`/releases`), Baptiste voulait `v0.1.0` (premier vrai release) et non `v0.1.1` (né d'un simple fix CI) → besoin de revert + déplacer le tag. | Le pipeline de release (`.github/workflows/release.yml`, `pnpm release:*`) avait été construit et relu, mais jamais exercé de bout en bout avant ce jour -- plusieurs hypothèses implicites (config `pnpm/action-setup` suffisante par défaut, visibilité d'une release draft, premier tag = version finale) invalidées une par une au premier run réel, pas en amont. | 1) `packageManager` ajouté à `package.json`. 2) Réexpliqué où trouver un draft (`/releases`, pas `/tags`). 3) Version revert 0.1.1→0.1.0 (nouveau commit) + `git tag -f v0.1.0 <commit>` (autorisé, contrairement à `git tag -d` bloqué dans les permissions globales de Baptiste) + `git push --force origin v0.1.0` -- **validé explicitement par Baptiste avant exécution**, le push avait été refusé une première fois par ses settings. Tag `v0.1.1` (devenu orphelin) laissé à sa charge pour le nettoyage local (`git tag -d`). | résolu |
