# LRN-033 — Découpler `AlertDialog` de son `Trigger` pour le piloter depuis plusieurs boutons

| Pattern observé                                                                                                                                                                                                                                                                                                                                                                                                             | Contexte                                                                                                                                                                                                                                                                      | Application future                                                                                                                                                                                                                 |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Un `AlertDialog` (Root+Content) contrôlé par state (`open`/`onOpenChange`) n'a pas besoin d'`AlertDialogTrigger` pour s'ouvrir -- n'importe quel bouton peut appeler `setOpen(true)` directement. Ça permet à un seul dialog d'être déclenché depuis plusieurs boutons rendus à des endroits différents du DOM (ex. deux positions responsive), sans dupliquer le dialog lui-même ni gérer deux states d'ouverture séparés. | `ResetButtons` (`AvatarPicker.tsx`) rendu deux fois pour occuper deux positions responsive différentes (large sous la description, étroit après les swatches) -- dupliquer aussi l'`AlertDialogTrigger` aurait dupliqué le dialog de confirmation ou désynchronisé son state. | Dès qu'un même dialog de confirmation doit être accessible depuis 2+ emplacements DOM (responsive, carte + footer, etc.), garder le dialog unique et contrôlé, ne dupliquer que le bouton déclencheur qui appelle `setOpen(true)`. |
