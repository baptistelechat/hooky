# BDR-076 — Exception ciblée à BDR-074 : détail CLI affiché pour le cas "refresh token mort"

| Décision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | Pourquoi                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Alternatives considérées                                                                                 | Statut |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- | ------ |
| `fetch_usage` détecte `refreshTokenExpiresAt` passé (cf. `refresh_token_expired`, `REFRESH_TOKEN_EXPIRED_ERR`) et court-circuite l'appel de refresh (toujours 429 dans ce cas, cf. ZBLK-033). `hooky-usage-error` porte désormais `{ consecutiveFailures, reconnectRequired }` au lieu d'un simple compteur. `UsagePanel` affiche "Reconnexion requise (claude auth login)" pour CE cas précis uniquement -- le message générique "Quotas indisponibles" (BDR-074) reste inchangé pour tout autre échec (réseau, API down, rate-limit transitoire). | [BDR-074](../decisions/BDR-074.md) avait explicitement écarté un message avec détail CLI pour rester minimaliste, sur la base d'un échec générique impossible à diagnostiquer côté UI. Ce nouveau cas est différent : il est détectable avec certitude (champ de date dépassé, pas une supposition), permanent tant que l'action n'est pas faite (contrairement à un 429 qui se résorbe seul), et le panneau martelait le poller (backoff jusqu'à 15min) sans que Baptiste sache qu'une action de sa part était nécessaire -- confirmé en le vivant en direct : `claude auth login` a corrigé `.credentials.json` mais le panneau restait bloqué jusqu'au redémarrage de Hooky (poller déjà en backoff sur l'ancien état). Demandé explicitement par Baptiste, qui a tranché pour garder le détail CLI plutôt que d'aligner sur BDR-074 (cf. question posée en session). | Message générique "Reconnexion requise" sans détail CLI (alignerait sur BDR-074) -- écarté par Baptiste. | actif  |
