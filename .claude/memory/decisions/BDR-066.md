# BDR-066 — Checklist `docs/RELEASE.md` (BDR-064) implémentée via 5 subagents parallèles

| Décision                                                                                                                                                                                                                                                                                                                                                              | Pourquoi                                                                                                                                                                                                                                         | Alternatives considérées                                                                                                                                                                                  | Statut |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| 7 points de la checklist v0 (icônes, tray, NSIS, auto-launch, commande hooks, mise à jour, CI) traités en une seule passe via 5 agents lancés en parallèle, groupés par fichiers non-partagés (icônes / `tauri.conf.json` / hook PowerShell / CI yaml séparés ; tray+settings+update regroupés dans un seul agent car tous trois touchent `lib.rs` et `Settings/**`). | Baptiste a explicitement demandé la parallélisation pour finir vite. Le risque réel était deux agents éditant le même fichier en même temps (`lib.rs`, `Settings/index.tsx`) — d'où le regroupement plutôt que 7 agents pleinement indépendants. | 7 agents un par point (rejeté : `lib.rs` et `Settings/**` auraient été édités concurremment par 3 agents différents, risque de conflits d'édition/écrasement).                                            | actif  |
| Auto-launch `SessionStart` : one-liner PowerShell inline dans `claude-settings-snippet.json` (try curl, catch → `Start-Process Hooky.exe`), pas de fichier `.ps1` séparé.                                                                                                                                                                                             | Un fichier externe casserait la propriété "portable sans script à copier" déjà documentée dans `docs/hooks/README.md`, et pose un problème d'œuf-et-poule (où le placer avant même que Hooky soit installé).                                     | Script `.ps1` séparé livré par l'installeur NSIS (rejeté : ajoute de la complexité d'installeur pour un gain marginal — pas encore testé en conditions réelles, à valider).                               | actif  |
| Badge "mise à jour disponible" : point rouge (`bg-destructive`) sur le bouton "Vérifier les mises à jour" + l'onglet Réglages, PAS de réutilisation du composant `AnimationOverlay` (badge des hooks sur le pet).                                                                                                                                                     | `AnimationOverlay` était hors du scope de fichiers alloué à l'agent (isolation entre agents parallèles) et trop couplé au rendu avatar/hooks pour être génériquement réutilisable sans risque de régression.                                     | Réutiliser `AnimationOverlay` tel quel (rejeté par l'agent faute d'accès au fichier ; à reconsidérer si le placement actuel (settings) s'avère peu visible à l'usage vs coin bas-gauche prévu au départ). | actif  |
| État "update disponible" partagé cross-fenêtre via `localStorage` + event Tauri (`src/lib/updateStatus.ts`), pas de store Zustand.                                                                                                                                                                                                                                    | Aucune dépendance Zustand dans ce projet malgré la préférence stack globale — le pattern `settings.ts`/`useSettings.ts` (localStorage + `emit`/`listen`) est déjà le mécanisme d'état partagé établi, pas de raison d'en introduire un second.   | Introduire Zustand pour ce seul besoin (rejeté, sur-ingénierie pour un seul flag booléen).                                                                                                                | actif  |

**Reste à faire** : tester le hook auto-launch en conditions réelles (session Claude Code, app fermée) ; re-lier chaque case cochée de `RELEASE.md` à une entrée `ROADMAP.md` (convention du projet, pas encore faite) ; landing page `hooky.vercel.app` (validée par Baptiste pour plus tard, non commencée).
