# BDR-077 — Pets Codex : scan live, union `procedural | sprite`, mapping à 3 niveaux

| Décision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Pourquoi                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Alternatives considérées                                                                                                                                                                            | Statut |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| Support des pets Codex (`~/.codex/pets`, spritesheet 8×9, cellule 192×208) décidé et planifié en Étape 12 de `docs/ROADMAP.md`, en 3 sessions. **Découverte** : commande Rust qui scanne le dossier en direct (pas de copie), images servies via le protocole `asset:` à scope limité à `~/.codex/pets/**`. **Identité** : `codex:<nom du dossier>`, jamais l'`id` du `pet.json` (collision constatée : dossier `ddo-zvzo-2` contient `id: "ddo-zvzo"`). **Rendu** : union `kind: "procedural" \| "sprite"` autour de `AvatarBundle`, nouveau composant sprite en CSS `steps()` / WAAPI. **Mapping à 3 niveaux** : lignes Codex (frames/fps), repli par état agrégé (9 états), surcharge optionnelle `codexAnimation` par entrée du catalogue de hooks. | Un `npx petdex install` doit apparaître sans étape d'import. Le `spritesheetPath` est contrôlé par l'auteur du pet (store public) : chemins absolus / `..` rejetés, extension `.webp`/`.png` uniquement, taille plafonnée, sinon le scope `asset:` exposerait n'importe quel fichier. Le repli par état existe car l'état agrégé multi-session peut différer du dernier hook affiché (même garde que `findMappingEntry` pour `PreToolUse`). Le champ `codexAnimation` sur les entrées existantes permet de distinguer ce que Cubee ne distinguait pas (`SessionStart` → `waving` vs `PermissionRequest` → `waiting`, tous deux `listening`) sans nouvelle UI dans la grille Animation. | Copier les pets dans les données de l'app (import) ; transmettre les images en base64 par IPC ; une seule table de mapping par état (perd la distinction par hook) ; identifier par l'`id` du JSON. | actif  |
