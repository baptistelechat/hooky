# BDR-014 — Composants en Tailwind, resets globaux gardés dans `App.css`

**Décision** : `App.css` supprimé puis recréé avec uniquement les resets globaux (`:root`, `html,body`, `#root`). Les 3 classes composant (`.pet-shell`, `.pet-window`, `.debug-overlay`) migrées en `className` Tailwind dans `Avatar.tsx` et restent hors d'`App.css`. `index.html` revert à l'état neutre (pas de classes Tailwind sur `html`/`body`/`#root`).

**Pourquoi** : Demande initiale de Baptiste : plus de fichier CSS séparé, tout en Tailwind pour rester cohérent avec le reste du projet (déjà 100% Tailwind côté Settings). Conversion complète (y compris les resets globaux vers `index.html`) jugée "trop forte" le lendemain — seule la migration des 3 classes composant (équivalent Tailwind naturel) était voulue

**Alternatives considérées** : Conversion 100% Tailwind y compris les resets globaux en `class=` sur `index.html` (tentée, revert le lendemain) ; garder `App.css` tel quel sans rien migrer (écartée, les 3 classes composant restent en Tailwind)
