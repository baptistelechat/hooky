# LRN-106 — Un git reset d'une autre session efface mon staging

| Pattern observé                                                                                                                                                                                                                                                                                                      | Contexte                                                                                                                                                                                                                                                                                                                                                                     | Application future                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Deux sessions Claude ouvertes dans le même dossier partagent **un seul working tree et un seul index** : le `git reset` de l'une efface le staging et les modifications de l'autre. Symptôme : `git commit` répond « nothing to commit » juste après un staging réussi, et le code supprimé réapparaît dans l'arbre. | `/session-close` sur Hooky : après un `git revert --no-commit` stagé et une gate lint + build verte, le commit est sorti vide. `git reflog --date=iso` montrait `reset: moving to 76b7850` à 08:19:59 ; `list_sessions` listait la session « Personnalisation de l'installateur Hooky » (`isRunning`, même `cwd`), dont les fichiers `src-tauri/installer/` étaient apparus. | Devant un commit vide ou un staging disparu : (1) `git reflog --date=iso` pour repérer un `reset:` ou `checkout:` inattendu ; (2) `list_sessions` pour trouver une session `isRunning` avec le même `cwd` ; (3) ne pas refaire l'opération en aveugle, prévenir l'utilisateur ; (4) refaire, stager par chemins explicites (jamais `git add -A`, cf. GLRN-300 en mémoire globale) et committer sans délai. Pour un gros chantier de suppression dans un dépôt partagé, un `git worktree` isolé évite la collision. |
