# LRN-017 — Un process de réémission périodique doit reconstruire le payload via la même logique que le handler principal

| Pattern observé                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Contexte                                                                                                                                                                                                                                                                                  | Application future                                                                                                                                                                                                                                                                                                                                           |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `spawn_idle_reaper` (tick 10s) construisait son propre payload minimal (`{ "state": resolved }`), différent de celui du handler principal `on_event` (`state` + `lastEvent` + `toolName` + `notificationType`). Son suivi interne (`last_emitted`) n'était jamais synchronisé avec les émissions du handler principal -- dès le premier tick suivant n'importe quel event, il se croyait "changé" et réémettait sa version tronquée, effaçant silencieusement `lastEvent` côté frontend sans que l'animation elle-même ait changé. | Symptôme : le badge d'icône (dépendant de `lastEvent`) disparaissait systématiquement dans les ~10s suivant chaque hook, alors que l'animation restait active. Plusieurs fausses pistes (interférence cross-session) avant de remonter au reaper en comparant les deux points d'émission. | Face à deux points d'émission d'un même type d'event (un handler synchrone + une tâche périodique de reconciliation/nettoyage), factoriser la construction du payload dans une fonction partagée plutôt que la dupliquer -- une réémission "de sécurité" qui simplifie son propre payload finit par désynchroniser silencieusement l'état côté consommateur. |
