# ZBLK-006 — Avatar invisible après relance : process confondu avec le vrai bug

| Friction                                                                                                                                                                                                                                                                                                                                                                                        | Cause réelle                                                                                                                                                                                                                                                                                                                                                                                                                                                            | Solution                                                                                                                                                                                                                                                                       | Statut |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------ |
| Après relance de `pnpm tauri:dev`, plus d'avatar visible mais l'icône tray présente. Premier diagnostic a suivi une fausse piste (conflit de port lié à une instance de fond restée active côté agent) et une tentative de diagnostic intrusive via automatisation d'écran (vol de focus + envoi de touches à l'aveugle sur la fenêtre de l'utilisateur, abandonnée après avoir raté sa cible). | En réalité deux causes distinctes cumulées dans la session : (1) une instance de fond retenait effectivement les ports, résolue en la tuant ; (2) le vrai bug, découvert seulement après que Baptiste a lui-même identifié le lien avec un changement récent d'`avatar.json` -- l'avatar "Onee" testé avait des valeurs de roundness hors bornes du schéma de validation runtime, provoquant un throw synchrone non catché (cf. [LRN-013](../../learnings/LRN-013.md)). | Ports libérés pour la première cause. Pour la seconde : lecture du dist du package `@bible-strong/avatar-core` pour remonter au schéma ajv exact et identifier les champs en cause, puis clamp automatique dans `avatarDefinition.ts` ([BDR-017](../../decisions/BDR-017.md)). | résolu |
