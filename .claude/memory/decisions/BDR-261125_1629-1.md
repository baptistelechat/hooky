# BDR-261125_1629-1 — Open Bot Avatar : 4ᵉ type d'avatar `bot:`, regard libre

**Décision** : `open-bot-avatar` (MIT, Dominik Scholz) est consommé en dépendance npm comme 4ᵉ type d'avatar (`kind: "bot"`, ids `bot:<id>`). Livrés : les 7 bots de départ du package + 16 bots de sa galerie copiés dans `src/components/bots/*.json` avec `colors.json` (couleur par défaut de chacun) et un README d'attribution. Rendu : `mountAvatar` monté une fois, tout le reste passe par `update()` (état, couleur, humeur, matière : aucun remontage). Le regard suit le curseur global dans tous les états **sauf `sleeping`**, un état custom (`AvatarStateDefinition`, `blink: 1`). Humeur (neutre/joyeux), matière (plat/fourrure/verre) et suivi du curseur sont des réglages globaux (`botMood`, `botMaterial`, `botFollowCursor`) ; les couleurs restent par avatar dans `avatarColorOverrides`. Import d'un bot du générateur : collage, Ctrl+V ou `.json`, validé par `validateAvatar`, stocké en localStorage (`hooky-custom-bots`, id `bot:custom-<uuid>`). Le JSON du générateur n'a pas de couleur (géométrie seule, par conception) : un bot importé prend une couleur de la palette de la galerie déduite de son id.

**Pourquoi** : contrairement à Cubee, ce moteur gère le regard indépendamment de l'état joué : suivre le curseur n'entre pas en conflit avec les animations pilotées par les hooks. Ce moteur assouplit donc [BDR-003](BDR-003.md) et [BDR-090](BDR-090.md), qui restent valables pour Cubee et les pets Codex. Licence MIT compatible avec l'AGPL du repo.

**Alternatives considérées** : `followPointer` seul (aveugle hors de la fenêtre 240 px) ; humeur/matière par avatar (YAGNI) ; ne livrer que les 7 starters ; stocker une couleur à l'import (changerait le format de stockage, les bots déjà importés resteraient orange).
