# LRN-066 — Porter un mécanisme de compensation visuelle en entier lors d'une ré-architecture, pas seulement le code qui semble s'y rattacher

| Pattern observé                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Contexte                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Application future                                                                                                                                                                                                                                                                                                                                                                     |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Un mécanisme de compensation visuelle (un élément qui se décale pour rester visible, un autre qui compense en sens inverse pour garder son alignement logique) peut sembler ne dépendre que du code "évident" (le positionnement du conteneur) lors d'une ré-architecture -- mais s'il reposait implicitement sur une propriété de l'ancienne architecture (ex: un conteneur délibérément surdimensionné), la retirer sans la remplacer casse le mécanisme SILENCIEUSEMENT : aucune erreur, juste un décalage visuel qui ne se manifeste que dans un cas particulier (élément proche d'un bord), invisible en usage courant. | Migration de la bulle de notification Hooky d'une fenêtre unique surdimensionnée (CSS `shiftX` sur le contenu + pointe compensée en sens inverse) vers une fenêtre dédiée plus petite, initialement clampée au moniteur -- le clamp remplaçait implicitement le rôle du surdimensionnement SANS reproduire `shiftX`, décentrant la pointe de la bulle par rapport à l'avatar dès que celui-ci était proche d'un bord d'écran (cf. [BDR-057](../decisions/BDR-057.md)/[BLK-027](../blockers/BLK-027.md)). | Avant de considérer un portage d'architecture terminé, énumérer explicitement les comportements visuels GARANTIS par l'ancien code (pas seulement les lignes déplacées) et vérifier que chacun a un équivalent dans le nouveau -- en particulier les compensations qui dépendaient d'une propriété implicite (une marge, une taille surdimensionnée) plutôt que d'un calcul explicite. |
