# LRN-071 — État CSS live ne doit jamais dépasser une opération OS débouncée qui définit ses propres bornes physiques

| Pattern observé                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Contexte                                                                                                                                                                                                                                                                                                                                                                                                            | Application future                                                                                                                                                                                                                                                                                                                                                                      |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Un state React qui pilote directement du CSS (taille, position...) et une action OS asynchrone/débouncée censée l'accompagner (ici `setSize()` de fenêtre Tauri) ne doivent JAMAIS lire deux sources différentes : si le CSS suit le state "live" (mis à jour à chaque tick) pendant que l'action OS attend la fin d'un debounce, le contenu peut transitoirement dépasser les bornes physiques réelles (encore à l'ancienne taille) et se faire rogner, ou décaler visuellement une fois l'action OS enfin appliquée. | Fenêtre "main" de Hooky dimensionnée sur `avatarSize` (slider Settings, plusieurs ticks/seconde pendant un drag) : le CSS de l'avatar suivait `settings.avatarSize` en direct, le `setSize()` OS était débouncé 120ms pour éviter un resize par tick — l'avatar grandissait donc visuellement au-delà d'une fenêtre encore trop petite pendant toute la durée du debounce (cf. [BDR-063](../decisions/BDR-063.md)). | Faire lire au CSS un state intermédiaire ("rendered"/"applied") mis à jour dans le MÊME callback (même `setTimeout`/`then`) que l'action OS/asynchrone, plutôt que le state brut qui change à chaque frame/tick — le state brut ne sert plus qu'à déclencher le debounce, jamais à peindre directement quand une contrainte physique externe (fenêtre, conteneur mesuré...) est en jeu. |
