# ZBLK-033 — "Chargement…" persistant malgré le fix backoff (révise ZBLK-032)

| Friction                                                                                                                                                                                                    | Cause réelle                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Solution                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Statut |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| Bulle bloquée sur "Chargement…" depuis 19h30 (constaté à 22h30, soit 3h) alors que [BDR-071](../../decisions/BDR-071.md) (backoff exponentiel) était censé régler ce symptôme dans [ZBLK-032](ZBLK-032.md). | Deuxième cause, distincte du rate-limit initial : le token OAuth local (`~/.claude/.credentials.json`) était expiré depuis **3 jours**, jamais rafraîchi. Seul le CLI `claude` en terminal rafraîchit ce fichier (via son `refreshToken`) -- Baptiste n'utilise quasiment plus que l'app Desktop (onglet Code), qui ne le touche jamais. `fetch_usage` retentait donc en boucle avec un token mort, l'API renvoyant 429 au lieu d'un 401 propre pour ce cas. Confirmé en relançant `hooky.exe` avec stderr redirigé (`fetch_usage a échoué : l'API usage a répondu 429`) puis en vérifiant `expiresAt` via PowerShell, et en observant qu'une vraie session `claude` déclenchait bien le refresh (`expiresAt` passé de 3 jours dans le passé à ~8h dans le futur). | Refresh OAuth direct implémenté côté Hooky (cf. [BDR-073](../../decisions/BDR-073.md)) + garde-fou UI distinguant chargement/échec (cf. [BDR-074](../../decisions/BDR-074.md)). **Validé en conditions réelles le lendemain (2026-09-12, 11h32)** : `pnpm tauri:dev` relancé après l'expiration naturelle du token (06h37) a déclenché `refresh_oauth_token` dès le premier cycle -- `expiresAt` passé de "expiré" à une nouvelle valeur exactement 8h après le `LastWriteTime` du fichier (11:32:57 → 19:32:57), aucune ligne d'erreur `[hooky-usage]` dans le terminal. Preuve indirecte (horodatage fichier + silence des logs d'erreur) mais concordante sur tous les points. | résolu |
