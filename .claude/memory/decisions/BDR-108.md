# BDR-108 — Sprites du mod générés dans l'app, stockés hors repo

| Décision | Pourquoi | Alternatives considérées | Statut |
| --- | --- | --- | --- |
| Hooky génère lui-même (`src/lib/modSprites.ts`, canvas) les SVG de chaque animation de l'avatar actif et les écrit via les commandes Rust `write_mod_sprite` / `mark_mod_sprites_ready` dans `app_local_data_dir/mod-sprites/<avatar>-<couleurs>/` ; `GET /state` indique `spritesDir` et `spriteKey` | Un mod n'a ni script ni DOM, donc ne peut pas rendre un avatar ; le front connaît tous les avatars (défauts, customs, pets Codex) et la couleur effective. Hors repo : `~/.claude/mods` est un lien vers un dépôt perso, ~1 Mo de SVG par avatar n'y a rien à faire | Scripts Node + Python lancés à la main (utilisés pour la v1, supprimés) ; sprites dans le dossier du mod ; export manuel depuis les réglages | actif (génération pas encore fiable, cf. BLK-045) |
