# LRN-074 — Merge JSON idempotent par identité stable, jamais par égalité de texte exacte

`install_claude_hooks` (`lib.rs`, cf. [[BDR-066]]) déduplique en comparant chaque entrée du
snippet à celles déjà présentes via `existing_arr.contains(entry)` — égalité **structurelle
exacte**. Le jour même, la commande `SessionStart` du snippet a changé (ajout du fallback
auto-launch, cf. [[BDR-066]]) : l'entrée déjà installée sur la machine de test ne matchait
plus la nouvelle, donc au lieu d'être remplacée, la nouvelle version s'est **ajoutée en
plus** — deux commandes Hooky concurrentes sous `SessionStart` dans
`~/.claude/settings.json`, constaté en test manuel par Baptiste.

**Pourquoi** : une comparaison par égalité exacte ne peut identifier "cette entrée est une
ancienne version de la mienne" — seulement "cette entrée est identique à la mienne, mot
pour mot". Tout changement futur du snippet (même mineur) recrée la même régression pour
tous les utilisateurs ayant déjà cliqué "Installer les hooks" une fois.

**Fix** : identifier les entrées "possédées" par un marqueur stable et indépendant du texte
exact — ici l'URL/port fixe `127.0.0.1:4242` (BDR-002, jamais réutilisé ailleurs). Le merge
retire d'abord toute entrée matchant ce marqueur, puis réinsère la version courante du
snippet. Idempotent par construction, y compris à travers les évolutions du snippet.

**Comment l'appliquer** : tout merge de config qui peut être réappliqué avec un contenu
source différent (config déclarative versionnée, snippet embarqué, etc.) doit dédupliquer
par une **identité stable** (id, port, clé de marqueur) — jamais par égalité de valeur
complète, qui casse silencieusement dès que la valeur source évolue.
