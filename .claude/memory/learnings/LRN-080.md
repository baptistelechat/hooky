# LRN-080 — `cargo metadata --no-deps` ne réécrit pas la propre version du package dans `Cargo.lock`

**Pattern observé** : `cargo metadata --format-version 1 --no-deps` ne force pas la resynchronisation de la propre entrée de version du package local dans `Cargo.lock`, même quand `Cargo.toml` vient d'être modifié -- `cargo check` (ou tout build réel) est nécessaire pour ça.

**Contexte** : `scripts/sync-version.mjs` ([BDR-067](../decisions/BDR-067.md)) utilisait `cargo metadata --no-deps` en supposant que ça suffisait. La release v0.2.0 a montré `Cargo.toml` à jour (`0.2.0`) mais `Cargo.lock` resté sur `0.1.0` pour l'entrée `hooky` elle-même -- confirmé en reproduisant volontairement le désync (bump manuel de `Cargo.toml`) puis en vérifiant que `cargo check` le corrige, `cargo metadata --no-deps` non.

**Application future** : Pour tout script d'automatisation de version touchant `Cargo.toml`, utiliser `cargo check` (ou `cargo build`) pour rafraîchir `Cargo.lock`, jamais `cargo metadata --no-deps` seul.
