# BDR-068 — Changelog Keep a Changelog, corps de release généré depuis `CHANGELOG.md`

**Décision** : `CHANGELOG.md` format [Keep a Changelog](https://keepachangelog.com/en/1.0.0/). `scripts/changelog-release.mjs` bascule `## [Unreleased]` vers `## [X.Y.Z] - date` dans le hook `"version"` de `pnpm version` -- **bloque le bump si Unreleased est vide** plutôt que de laisser passer une release sans note. `scripts/changelog-extract.mjs` sort le texte d'une section donnée, utilisé par la CI (`releaseBody` de `tauri-action`) et à la main. Nouveau skill global `/changelog` pour alimenter `Unreleased` en routine, curation stricte (jamais de dump de commits).

**Pourquoi** : `generateReleaseNotes` de `tauri-action` (défaut `false`, jamais configuré) produisait un corps de release quasi vide sur la toute première release -- juste un lien "Full Changelog" sans liste. Keep a Changelog explicite : _"Changelogs are for humans, not machines"_, un générateur de commits ne remplace pas une note curée.

**Alternatives considérées** : `generateReleaseNotes: true` seul (rejeté : liste brute de commits/PRs, pas une vraie note produit, et vide/pauvre sur une première release sans tag précédent) ; changelog entièrement manuel sans script ni skill (rejeté : aucun garde-fou contre l'oubli, exactement le problème rencontré).
